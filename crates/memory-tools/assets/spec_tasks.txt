Descompone un `spec` ya propuesto (ver `spec_propose`) en tareas concretas, cada una un concepto `type: task` enlazado de vuelta al spec (`[[implements:<spec_id>]]`) con tag `status-pending`. Se crean en un solo lote (no atómico: cada tarea se aplica o se descarta por su cuenta). Cada tarea admite `depends_on` (lista de títulos de otras tareas de ESTE MISMO lote, o concept_ids de tareas ya existentes) — `spec_status` usa esos enlaces `[[depends_on:...]]` para no marcar como "próxima a hacer" una tarea cuyas dependencias no están todas `done`. Para avanzar una tarea después, usa `memory_patch` sobre su `concept_id` cambiando el tag `status-*` (`status-pending` → `status-in_progress` → `status-done`, o `status-blocked`); no hace falta otra herramienta para eso. Antes de `status-done`, añade con `memory_commit` una sección `## Evidencia` al cuerpo (comandos ejecutados y resultados reales) — `memory_patch` rechaza el paso a `status-done` sin ella (gauntlet de old-coder: github.com/AmazingAng/old-coder).
