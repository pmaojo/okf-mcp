Aplica un lote de patches de frontmatter (mismos campos que memory_patch: set/remove/add_tags/remove_tags, nunca el cuerpo) en una sola llamada. Es la alternativa a construir el lote a mano con memory_bulk_commit reenviando el markdown completo de cada concepto — aquí cada item solo lleva lo que cambia. REGLA OPERATIVA: cada item de `patches` requiere concept_id, expected_hash y reason, igual que memory_patch. Si `atomic` es true (por defecto), un fallo de CUALQUIER item — documento inexistente, conflicto de CAS, o el gauntlet de old-coder bloqueando `status-done` en una tarea sin sección `## Evidencia` — descarta el lote entero: nada se persiste. Con `atomic` false cada item se aplica o falla por su cuenta y los demás no se ven afectados.
